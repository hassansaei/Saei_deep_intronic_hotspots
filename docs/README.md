# ISHMap browser (GitHub Pages)

Static gene browser for the genome-wide deep-intronic splice interval screen.
GitHub Pages serves this folder (`Settings` → Pages → Deploy from branch `main` → `/docs`).

Live site (after Pages deploy):

- https://hassansaei.github.io/Saei_deep_intronic_hotspots/
- Legacy clone URL may still redirect from `Saei_COL4A5_Intron6_hotspot`

This folder is the published site root. Analysis outputs under `genome_wide/` stay local and gitignored. Only the slim JSON/CSV payload under `docs/data/` is committed for the browser.

## How the site is framed

| Layer | Role |
|---|---|
| Pages UI (`index.html`, `gene.html`, `about.html`) | Search, gene summary, interval table, inline SVG plots |
| `docs/data/` | Generated payload the UI fetches (never hand-edit) |
| `scripts/prepare_release.py` + `config.json` | Build `docs/data/` from `genome_wide/` |
| Zenodo (separate step) | Full tables and PNG plots; not fetched per gene by the site |

**Unit on the gene page:** interior significant **intervals**, not “one hotspot per gene”.

- Source table: `genome_wide/results/shortlist_interior_hotspots.csv`
- Sort / default selection: lowest `min_BH_q`
- `top` chip: best-q interval within each intron
- Concentration: spliceogenic variants in the interval / spliceogenic variants in that intron interior
- Transcript / exons: the RefSeq model used for the screen (`transcript.json` + `ncbiRefSeq.txt`), not a separate MANE Select pick
- Variants on the plot: Moderate/High only (`alphagenome_splicing >= 0.56`), capped at 3,000 per gene

Genes in the browser: the 4,963 rows in `gene_hotspot_summary.csv`. Single-exon disease genes and loci with no Atlas rows are omitted here; they belong in the Zenodo `not_scored.tsv` when that release is built.

## Layout

```text
docs/
  index.html              Home / gene search
  gene.html               Gene page (?g=COL4A5&iv=IV-1)
  about.html              Methods and column notes
  .nojekyll               Keep GitHub Pages from running Jekyll
  assets/
    css/site.css
    js/{home,app,gene,plots,analytics}.js
    img/logo.png
  data/                   GENERATED by prepare_release.py web
    index.json
    genes/<GENE>.json
    downloads/<GENE>_intervals.csv
  README.md               This file
```

Relative paths only (`assets/...`, `data/...`) so project Pages under `/<repo>/` work without a hard-coded base URL.

## Regenerate website data

Run from the **repository root** (Python 3.8+, standard library only). Requires a completed local `genome_wide/` screen and `notebooks/01_alphagenome_analysis/ISM/ncbiRefSeq.txt`.

```bash
# Optional: confirm paths in config.json
# summary_csv  -> genome_wide/results/gene_hotspot_summary.csv
# hotspots_csv -> genome_wide/results/shortlist_interior_hotspots.csv
# genes_dir    -> genome_wide/genes
# refseq       -> notebooks/01_alphagenome_analysis/ISM/ncbiRefSeq.txt

python scripts/prepare_release.py web \
  --config config.json \
  --out docs/data \
  --workers 8
```

Check the printed size. Keep `docs/data` well under ~500 MB (GitHub Pages soft limit 1 GB). Confirm:

- `docs/data/index.json` → `meta.n_genes` matches the scored set (4,963 for v1.0)
- `docs/data/genes/COL4A5.json` has `intervals` (not `hotspots`), exons, and `IV-1` as `default`
- Downloads are named `*_intervals.csv`

Do **not** run a full `inventory` walk on this tree unless you need a fresh folder survey. It rescans hundreds of thousands of files and can guess the wrong summary tables. Prefer the hand-written `config.json`.

UI HTML/CSS/JS under `docs/` are edited directly. Regenerating `web` only rewrites `docs/data/`.

## Preview locally

`file://` will not load JSON via `fetch`. Serve the folder:

```bash
python3 -m http.server -d docs 8000
```

Open http://localhost:8000/ then try http://localhost:8000/gene.html?g=COL4A5.

## Publish an update

1. Rebuild `docs/data/` if scores or intervals changed (`prepare_release.py web` above).
2. Edit pages under `docs/` if the UI changed.
3. Commit and push `main` (include `docs/`).

```bash
git add docs/ config.json scripts/prepare_release.py
git status
git commit -m "$(cat <<'EOF'
feat: Update ISHMap Pages data or UI

EOF
)"
git push origin main
```

GitHub Pages rebuilds from `/docs` on `main`. Allow a few minutes, then hard-refresh the live URL.

## Zenodo full release (optional, separate from Pages)

Chromosome zips and plots are **not** required for the browser. When depositing the full atlas:

```bash
python scripts/prepare_release.py zenodo --config config.json --out release
```

Omit `--include-svg` unless the archive stays under Zenodo’s size limit. Reserve the DOI first, put it in `config.json` → `release`, then wire gene-page Zenodo links. Until then the UI keeps the “DOI not reserved yet” notice.
